## Goal

The AI harness works end-to-end from **both Claude Code and Codex**: skills load in both tools
(Codex skill loading verified structurally by adapter tests, per ADR-0137),
gates run on Windows/macOS/Linux (as built: verified on Windows only; `gates.yml` lint + first
CI run handed to M1 row 18), review verdicts bind to staged diffs, every gate is proven to
fail on a deliberately broken input. After M0 an agent can drive M1 unattended **once M1's
first row closes the descoping loophole** (M0 final review F1).

> **Scope change 2026-09-26 (user decision):** the interactive `/goal` dry runs (rows 14/15) were
> descoped from M0 and reviews use isolated subagents only; see the roadmap "Deferred" table.
> The dry-runs completion leg was removed accordingly (task M0.26).

Already present at the start of M0 (written during project setup, not yet executed — no Node
was installed): `AGENTS.md`, `CLAUDE.md`, `.agents/skills/*`, `.claude/agents|skills|settings`,
`scripts/gates/{lib,thresholds,precommit,check-portability,check-commit-msg,check-reviewed,m0-complete}.mjs`,
`scripts/harness/{review,run-reviewer,sync-skills,setup}.mjs`, `.githooks/*`, `.harness/*`.

## Risks

| Risk | Signal | Mitigation |
|---|---|---|
| Built-in `/goal` semantics change | dry run behaves differently | Keep `stop-check.mjs` as deterministic fallback |
| Windows shell differences | hooks not firing | Node-only scripts; `.githooks` call `node` directly |
| Reviewer CLI unavailable/costly | run-reviewer fails | Subagent fallback documented in `code-review` skill |

## Learned

- Evidence legs that need a human or a vendor CLI (dry runs, cross-vendor smoke) must be planned
  as blockable up front, with CLI-free kits, instead of being discovered at the end.
- A state value that closes rows (`descoped`) must never be review-exempt; gate-honesty legs belong
  in the first rows of a milestone, not added by checkpoint reviews (18 planned rows became 26).
- Checkpoint reviews every ~8 commits caught real gate holes each time; keep the cadence.
