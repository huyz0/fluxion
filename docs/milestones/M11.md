## Goal

The player works everywhere a deck is viewed: in the studio, in any `.flux.html`, and embedded
as `<fluxion-player>`. It presents full-screen with letterboxing and navigates by keyboard,
clicker, click, touch and deep link. It never lets content be edited, announces screens to
assistive technology, and stays within 150 kB gzip. The R1 demo `examples/r1-mvp-deck.flux.html`
shows the product: a 5-screen deck built by hand in the studio, saved, reopened and presented
full-screen. This milestone closes increment R1.

## Decide before coding

- ADR-0026: player packaging. Covers the `<fluxion-player>` custom element with shadow DOM and
  React inside, adopted content CSS, `::part()` chrome, the React wrapper at
  `@fluxion/player/react`, what goes in the player core chunk vs lazy chunks, and whether Zod
  validation runs in the player or is trusted from the loader.
- ADR-0027: observability and privacy. Covers the `Logger` port implementation (namespaces,
  levels), the debug overlay, the diagnostic-report fields (no content), and the no-telemetry
  default with the network test that enforces it.
- New thresholds (added in task 1 per `testing.md` rule 17): `OPEN_50_SCREENS_MS_DESKTOP` 1500,
  `OPEN_50_SCREENS_MS_MOBILE` 3000, `EDITOR_TTI_MS` 2500.

## Scope / Non-scope

- In: `PresentationController`, minimal build reduction in `anim`, fullscreen + letterbox,
  keyboard/clicker/overview navigation, read-only enforcement, deep links + history, progress
  chrome, the web component + React wrapper, touch gestures, orientation/resize, a11y structure
  + live region, keyboard-only presenting, size/perf budgets, logging/debug overlay, diagnostic
  report, no-telemetry test, the browser matrix, the R1 demo and exit.
- Out: effects/transitions/builds editor (R4), speaker view and presenter tools (R5),
  responsive reflow and scroll mode (R7), kiosk auto-advance (M22).

## Risks

| Risk | Signal | Mitigation |
|---|---|---|
| Player core over 150 kB with React + Zod + fflate | size-limit red at task 13 | Measure from task 2; trust loader output in the player (ADR-0026); `DecompressionStream` instead of inflate code; lazy chunks |
| iOS Safari has no element Fullscreen API | letterbox spec fails on `mobile-safari` | Full-viewport fallback with `viewport-fit=cover`; document the limitation |
| Mobile open time > 3 s from base64 decode + React mount | `perf.open-50` mobile red | `Uint8Array.fromBase64`, render screen 1 before parsing the rest, preload the next screen only |
| webkit E2E flakiness blocks the exit | flake-report on webkit | Quarantine per `testing.md` §8 with a backlog row; the gate forbids open quarantines, so fix before exit |

## Handed off from M1 (final review)

- **Release enablement (before anyone sets `RELEASE_ENABLED`):** with no changesets,
  `changesets/action` publishes every unpublished version (M1.39: the first push tried all
  `@fluxion/*@0.0.0`). Before enabling: keep unreleased packages `private` (or publish only with a
  pending-changeset check), split publish into its own job behind the `npm` environment with a
  required reviewer (M1.21 F2), configure npm trusted publishing (OIDC), allow Actions to create
  PRs and give the Version Packages PR a GitHub App token so `ci.yml` runs on it (M1.21 F1)
  (M1 final F2).
- **Code scanning and dependency review:** CodeQL and `dependency-review-action` run only when repo
  variable `CODE_SCANNING` is `true` (a private repo has neither without GitHub Code Security).
  Before the first public release make the repo public or licensed, set the variable, and make
  `ci-ok` fail while it is unset on a public repo (M1 final F1; NFR-SEC-005).

## Handed off from M2 (final review)

- **fast-check out of @fluxion/schema's runtime dependencies:** the `./testing` entry made fast-check (and pure-rand) a runtime dependency of the published package; before any public publish move the testing helpers to a private or test-only package, or make fast-check an optional peer with a dependency-cruiser exception (M2 final F6).
