# M3 — Core engine: store, commands, undo, registries

| Increment | Depends on | Completion command |
|---|---|---|
| R0 | M2 | `node scripts/gates/m3-complete.mjs` |

## Goal

`@fluxion/core` is the only write path to a document. It provides a normalized record store
with per-record signals (alien-signals), transactions that emit record-level diffs, and
incremental indexes. Every mutation goes through a command; integrity hooks run inside the
transaction; undo/redo supports merge keys; and typed registries let built-ins and plugins
contribute through the same API. The engine is pure (ports for time, randomness, I/O), meets
the < 16 ms undo budget on 5 000 records, and is proven by property tests to undo back to the
initial document exactly.

## Requirements

FR-EXT-001 (part: core registries + kind-switch lint; render/editor registries land in M4/M6),
FR-EDT-006 (core: history, merging; UI in M7), NFR-REL-003, NFR-PERF-006, NFR-MNT-006,
NFR-REL-005 (carried: deterministic core).

## Decide before coding

- ADR-0002 is the reference for the store and undo design.
- ADR-0014: command and transaction semantics. Covers `mergeKey` coalescing rules (same key and
  no interleaved transaction), what undo metadata stores (selection/view as an opaque blob),
  integrity-hook ordering, and copy-on-write `store.fork()` semantics.

## Scope / Non-scope

- In: ports (`Clock`, `Random`, `TextMeasurer`, `FileIO`, `Hasher`, `Logger`) with test
  implementations, `RecordStore`, `transact`, `Diff`, indexes, queries, integrity hooks,
  `Registry<K,V>` and the core registries, `CommandDef` and registry, built-in record commands,
  the undo manager, `fork()`, the read-only policy guard, and benchmarks.
- Out: resolved styles/themes (M4), shape defs content (M5), editor session store (M6), undo UI
  (M7), CRDT bridge (post-1.0).

## Risks

| Risk | Signal | Mitigation |
|---|---|---|
| Dev-mode Zod validation per transaction makes merged drags slow | `transact-5000` bench > budget | Validate only changed records; disable in production builds via a flag, never in tests |
| alien-signals API churn or glitches with nested computeds | flaky subscriber counts | Wrap it behind a tiny `signals.ts` facade; pin through the catalog |
| Integrity hooks recurse or order-depend | property failures with cascades | Run hooks to a fixed point with a depth limit and deterministic order (ADR-0014) |
