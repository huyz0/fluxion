# M29 — Responsive & mobile reflow

| Increment | Depends on | Completion command |
|---|---|---|

## Goal

One document reads well on a projector, a laptop and a phone held upright. Each document or
screen chooses `fixed` (scale to fit), `reflow` (a per-breakpoint variant built from override
patches) or `scroll` (stacked, web-page-like, with scroll-driven builds). An author can generate
a portrait variant with one command, either heuristically or with AI. The variant has no
overlaps and keeps an effective font size of at least 14 px. Authors edit overrides in a
device-frame preview that never touches the base layout. Themes come in light/dark pairs that
can follow the viewer's OS setting.

## Decide before coding

- **ADR-0119 Breakpoint resolution and baked variants.**
  - The first matching `BreakpointDef` wins.
  - Resolution order is `base → bp → state → bindings`.
  - Layout results are baked per `(screenId, bpId)` into `bp:` patches, so the player never runs
    layout.
  - An orientation switch tweens between the baked geometries.
- **ADR-0120 Scroll-driven mode.** Compare IntersectionObserver-driven step progress with CSS
  `ScrollTimeline`, and choose based on engine support and `file://` behaviour. The ADR also
  fixes snapping under reduced motion, and pausing and unmounting of off-screen screens.
- **ADR-0121 Light/dark theme pairs.** Themes are paired by `theme.pair` id. `prefers-color-scheme`
  is used only when the document enables it. The ADR also covers how exports and the site choose
  a variant.
- Reference: 10 §1–4, ADR-0005 (layout pipeline).
