# M8 — Arrange, screens & library v1

| Increment | Depends on | Completion command |
|---|---|---|
| R1 | M7 | `node scripts/gates/m8-complete.mjs` |

## Goal

Users can structure a deck. They add, duplicate, reorder, rename, hide and section screens in a
thumbnail navigator, pick screen presets or an infinite canvas, and write speaker notes. On the
canvas they group and ungroup, align, distribute, change z-order and snap with smart guides.
They find shapes in a searchable library and drop them onto the canvas. All operations are
undoable commands with minimal record diffs.

## Requirements

FR-ARR-001, FR-ARR-002, FR-ARR-003, FR-ARR-004, FR-ARR-005, FR-LIB-001, FR-LIB-002, FR-SCR-002
(part: "hidden screens skipped in present mode" is verified with the player in M11),
FR-SCR-003, FR-SCR-004 (part: site nav in M31), FR-SCR-006 (part: speaker-view display in M25), NFR-DX-002 (part: row 15b, the worst-case staged budget, handed off from M7).

## Decide before coding

- ADR-0021: screen sections model. Options are a new `section` record type or
  `screen.sectionId` plus document-level section metadata. The chosen option is added to the
  schema as a minor bump with a migration and a fixture. The ADR also covers the library search
  index (own prefix/keyword index vs MiniSearch) against the 10k-entry < 100 ms budget.

## Scope / Non-scope

- In: group/ungroup/enter-group, align, distribute, z-order, pure snapping engine + smart
  guides, screen commands, screens navigator with thumbnails, presets + infinite screen,
  sections, notes panel, library panel with search, drag/click insert.
- Out: containers/frames with clipping, match size, layers panel (M19), tidy-up/auto layout
  (M13/M17), shape import and packs beyond `basic` (M18), master screens (M19).

## Risks

| Risk | Signal | Mitigation |
|---|---|---|
| Thumbnails of many screens cost too much in the navigator | navigator open > 200 ms on 50 screens | Render thumbnails lazily in view with IntersectionObserver; cache per screen revision |
| Group transforms with rotated children break connector attachment | `FR-CON-012` property failures | Always derive world matrices from the parent chain; add group cases to the arbitraries |
| Sections decision leaks into site mode (R7) | ADR conflicts with FR-SITE nav needs | ADR-0021 must name site navigation as a consumer and keep ordering by fractional index |

## Learned

- cp1/cp2 (M8): the plan grew from 16 to 36 rows because it lacked a UI row for every core command (arrange, sections, notes), split big rows (navigator, library) and met CI failures only the CI matrix shows (webkit axe contrast, a slow macOS runner). Later plans list a UI row per command and a CI-matrix check.
- A document-model change that bumps the schema version touches every fixture and example: budget a row for it, and map `examples/` and `fixtures/` in the ladder scope.
- Group transforms: members keep screen coordinates and the group box follows them (ADR-0022, M8.34), not parent transforms applied to children.
