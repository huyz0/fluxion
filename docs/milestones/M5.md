# M5 — Shapes, anchors & basic connectors

| Increment | Depends on | Completion command |
|---|---|---|
| R1 | M4 | `node scripts/gates/m5-complete.mjs` |

## Goal

All 21 basic shapes render from parametric definitions supplied by `packs/basic` through the
SDK. The full style model applies (fills, strokes, effects, token refs), shape text is laid out
with auto-fit, and images can be cropped, fitted and masked. Connectors attach through floating
and named anchors and route as straight, curved, orthogonal (elbow) or polyline. They carry
markers and labels and stay attached under any transform. Routers are pluggable by name.

## Requirements

FR-SHP-002, FR-SHP-003 (part: parametric definitions + evaluation; handles and inspector in
M7), FR-SHP-004, FR-SHP-005, FR-SHP-006, FR-SHP-012, FR-CON-002, FR-CON-003, FR-CON-005,
FR-CON-006, FR-CON-012, FR-ANC-001, FR-ANC-002, FR-RTE-001.

## Decide before coding

- ADR-0016: shape outline representation and the path-template expression language. Covers
  the SVG path template with `w`, `h`, params, arithmetic and `min`/`max`, evaluated by a safe
  interpreter (no `eval`, step limit) that is later reused for bindings, as opposed to
  geometry functions by id. It also covers how outlines normalize to cubic paths.
- ADR-0005 (layout/routing stack) is the reference: the elbow router here is the simple
  version, and obstacle-avoiding A* comes in M16.

## Scope / Non-scope

- In: `ShapeDef` + `shapeDefs` registry, the expression interpreter, a minimal
  `@fluxion/sdk` `definePack`, `packs/basic`, outline/hit/perimeter functions, the full
  shape/connector views, `TextMeasurer` browser adapter (canvas) for shape text, image element
  view, anchor resolution, the router interface + 4 routers, markers, labels, and snapshots.
- Out: editing handles (M7), anchor kinds `side`/auto/dynamic, obstacle avoidance, line jumps
  (M16), asset import pipeline (M10; tests use in-memory assets), custom anchors (M16).

## Risks

| Risk | Signal | Mitigation |
|---|---|---|
| Canvas text metrics differ from DOM layout (fonts, subpixel) | grow-shape ±1 px test flaky across browsers | Verify with a batched DOM read for auto-size text only; await fonts; fixed-metrics fake in T0 |
| Stroke `align` (inside/outside) is not native in SVG | visual mismatch | Emulate with clipPath/double-width stroke; document the limitation per browser |
| 21 shapes exceed one commit each batch | diffs > 400 lines | Split batches further in the backlog; defs are data, views shared |

## Handed off from M4 (final review)

Each item becomes a row of M5's backlog when M5 is planned; F3 is the first row.

- **Check the last push's CI before a task (first row):** the drive loop reads the conclusion of main's last pushed CI run before starting a task and fixes a red run first; M4 kept landing commits on a red windows verify for seven tasks (M4 final F3).
- **Changeset leg from the range:** milestone gates take the changeset package list from the packages the milestone's range changed, not a literal list (M4 final F1).
- **Render reports what it rendered:** `renderDocumentToHtml` returns the ids of the screens it rendered with the HTML, and the CLI's `result.screens` uses them instead of a regex over the markup (M4 final F2).
- **Visual job must select a test:** `test:visual` drops `--pass-with-no-tests` now that @visual specs exist, and ci.yml's stale visual comment goes (M4 final F4).

## Learned

- cp1: definitions carried data no consumer read (defaultStyle; open outlines filled) and validation stopped at strings. A pack's data needs a consumer test the gate names, and `parseShapeDef` must prove the definition evaluates.
- cp1: rows grew to 31 of 19 planned; the ADR-heavy rows (M5.7, M5.12) ran past 800 lines. Split the routing rows (M5.16-M5.23) before starting them.
- cp1: a harness test running tzap in the checkout shared its Vite cache with the ladder's browser run (M5.29); a tool that starts Vitest takes its own cache.
