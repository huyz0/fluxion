# M19 — Advanced editing: containers, layers, paths, tables, masters

| Increment | Depends on | Completion command |
|---|---|---|
| R3 | M18 | `node scripts/gates/m19-complete.mjs` |

## Goal

The editor handles structured, production diagrams. Frames/containers clip and carry their
children; a layers panel shows the element tree with visibility, lock and drag-reorder; shapes
can have multiple text regions and icon slots, locks and flips; vector shapes support boolean
operations and vertex/bezier editing; tables are a native shape; master screens provide shared
backgrounds, placeholders and elements. Quick-connect handles and element search speed up
everyday diagramming.

## Decide before coding

- **ADR-0052 Frames & containment semantics** — `frame` record behaviour (clip, padding,
  child reparenting on drop, transform inheritance, interaction with live layouts from M17 and
  with groups), hit-testing inside clipped frames.
- **ADR-0053 Boolean path operations** — `polygon-clipping` (MIT) on adaptively flattened
  cubics with curve re-fit vs. `paper.js` path booleans (MIT, lazy chunk); precision targets;
  runs in `geometry` (pure) or a lazy editor chunk. Decided: `polybooljs` (MIT, no dependencies)
  in `geometry`, since polygon-clipping's dependency robust-predicates is Unlicense (cp1 F3).
- **ADR-0054 Masters and tables in the schema** — `screen.masterId`, placeholder mechanism and
  override precedence; `table` element (`rows`, `cols`, `cells`, merges, theme table styles);
  additive schema minor + migration fixture.

- Handed in from M8 (cp1 F2): the arrange UI for align to a key object, distribute by centres and tidy to equal gaps; the commands exist.

## Scope / Non-scope

- In: frames, match size / format painter, layers panel, text regions & icon slots, locks,
  flips (geometry + anchors), boolean ops, path editing tool, table shape + editing, master
  screens + editor, quick-connect, element search.
- Out: sub-screens / drill-down (M25); component shapes (M27); responsive overrides (M29);
  comments (M32).

## Risks

| Risk | Signal | Mitigation |
|---|---|---|
| Boolean ops on flattened curves produce jagged or huge paths | golden point count explodes; visual steps | Adaptive flattening + curve re-fit; tolerance in ADR-0053 |
| Frame vs group vs live-layout semantics tangle | conflicting reparent/undo bugs in E2E | One containment model in ADR-0052; property test on reparent + undo |
| Master inheritance breaks parity or export | parity diff > 0.1 % on master fixture | Masters rendered in background layer by the same `ScreenView` path in all modes |

## Learned

- cp1: plan reviews of contract ADRs ran long (M19.8 eight rounds); each new reference field reaches hooks, REFERENCE_PATHS and asset use, so list those surfaces up front.
- cp1: review minors deferred to a later row belong in that row's acceptance, not only in a commit body (ADR-0052 r2 → M19.10).
- cp1: whole-file gate legs prove little; name the cases (`named`) as each feature row lands.
- cp2: a named gate case can still pass on code nothing calls; check that it runs the path the user takes (frameTurned vs the editor's rotate handle).
- cp2: when a contract ADR lands, copy its Confirmation into the acceptance of each later row it names, in the same commit.
- cp2: each new command that resizes or restyles reopens the lock rows; list it in M19.15.
- cp3: a row that adds a menu or palette entry runs the e2e specs that list that menu; a core command that lands without UI adds a UI row or a descope in the same commit.
- cp3: a fixed sleep on a cross-page or async answer is a flake waiting for a loaded runner; fix every case in the file when one is fixed.
- cp4: a feature row adds its named gate cases and e2e legs in its own commit, and a review minor carried on goes into the receiving row's acceptance in the same commit; a budget target met by one CI reading proves nothing until the row's own runs repeat it.
- cp5: a commit that carries review minors creates or amends the receiving row in that commit and its body names it; a row's fallback paths get a case where the fallback differs from the obvious one (navigator vs id order).
- cp6: a row that changes what a spec reads (a menu, the decompiler's subset, a writable key, the Vitest config) greps e2e/ and tests/harness/ for it and runs those specs before review; docs rows land after the feature rows they describe.
- cp7: a feature row puts the tests and e2e specs its acceptance names on m19-complete legs in its own commit (cp4's rule, missed by M19.38, M19.40 and M19.43); a catch-all named-cases row collects drift. A harness reader of CI runs is tried from the agents' environment before it is relied on (gh's paged jobs read hit the proxy's 403).
- cp8: size a handed-off speed row as several rows when the plan is written, and plan a fix that depends on a non-reproducible failure as instrumentation now plus a later-milestone row.
- final: a checkpoint, not the row's commit, ratifies a narrowed scope, and a speed row's effect is read from readings taken after it, not a median that includes earlier ones.
