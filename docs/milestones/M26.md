# M26 — Plugin SDK & developer workflow

| Increment | Depends on | Completion command |
|---|---|---|
| R6 | M25 | `node scripts/gates/m26-complete.mjs` |

## Goal

Third parties can extend Fluxion through a versioned public `@fluxion/sdk`, and first-party
packs use exactly the same API. A plugin declares a manifest, contributes to player and editor
surfaces separately, loads lazily on first use, and can be installed, disabled, updated and
uninstalled. It can also carry schema-driven settings. A developer can go from `fluxion plugin
create` to a hot-reloading plugin in the dev studio in under a minute. Packs can also be listed
from remote registry URLs, with versions and hashes pinned.

## Requirements

FR-EXT-002, FR-EXT-003, FR-EXT-004, FR-EXT-005, FR-EXT-006, FR-EXT-007, FR-CLI-003 (part:
`plugin create`, `plugin validate`; `pack` with `.fluxpack` in M27), FR-LIB-010, NFR-MNT-007
(part: SDK API report).

## Decide before coding

- **ADR-0110 SDK public surface and release tags.**
  - Entry points: `@fluxion/sdk/{player,editor,manifest,testing}`.
  - `@public`, `@beta` and `@alpha` tagging.
  - The `engines.sdk` compatibility rule.
  - Which internal contracts are re-exported, and which stay internal.
- **ADR-0111 Plugin dev server protocol.** Vite plus a WebSocket bound to localhost only. The
  studio's `?plugin-dev=<url>` loads the plugin as user-trusted. Hot reload works by dispose then
  re-activate.
- **ADR-0112 Pack registry index v0.** A static JSON index gives, per package version, the
  artifact URL, sha256 integrity, engines and AI summary. M33 extends it with publisher
  signatures (FR-PKG-005).
- Reference: ADR-0007 (plugin trust and import-map model), 09 §2–5 and §10.

  - The manifest schema.

  - Activation events and lazy loading.
  - Lifecycle UI.
  - The player/editor surface split and its bundle check.
  - Migrating first-party packs onto the public SDK (dogfooding).
  - Plugin settings.
  - The CLI commands `plugin create`, `plugin dev` and `plugin validate`.
  - SDK testing utilities.
  - Remote registries.
  - Plugin author docs.
- Out:
  - The `.fluxpack` container, embedding in files, and the sandbox and trust prompts (M27).
  - React component elements (M27).
  - Signing (M33).

- `check-api-report`: the `@fluxion/sdk` report matches the committed report.
- Playwright `plugins.lazy-load`, `plugins.lifecycle`, `plugins.settings` and `registry.install`
  pass on chromium, firefox and webkit.
- The timed `plugin-dev.hot-reload` E2E stays under 60 s.
- CLI E2E runs on the OS matrix (NFR-PORT-004).
- dependency-cruiser: packs use only the SDK.
- Validate negative fixtures all exit 1.
- The size-limit player core is unchanged.
- `examples/packs/hello-shapes` validates and renders.
- No quarantines.
- The milestone-review verdict is recorded.

## Risks

| Risk | Signal | Mitigation |
|---|---|---|
| Dogfooding migration reveals missing SDK surface, bloating `@public` | Many `@internal` escapes requested | Tag new items `@beta`; ADR-0110 lists what may stay internal |
| Hot reload leaks registry entries or React roots | Duplicate shapes after reload | Disposable audit test: registry sizes equal before/after 10 reloads |
| One-minute DX target fails on Windows (install time) | Timed E2E > 60 s on windows runner | Pre-warmed pnpm store in template; measure scaffold and dev start separately |
