# ADR-0022 — Fonts are vendored OFL assets, the Google Fonts catalog is a snapshot fetched by the studio only, uploads are sniffed by magic bytes, and subsetting waits for M10

## Context and Problem Statement

FR-THM-008 asks for fonts from three sources: bundled open fonts, the Google Fonts catalog ("fetched and embedded on
save") and a local upload (WOFF2, TTF, OTF), and for an offline file to render with its embedded font. M9 delivers the
registry, the three sources and the picker; M10 delivers the file format work (embedding on save, subsetting). Four things
need deciding first: where the bundled files come from and under what licence, where the Google Fonts list comes from and
who fetches the files, what an upload may be, and what M9 leaves to M10. The licence allowlist of `check-licenses`
(MIT, Apache-2.0, BSD, ISC, 0BSD, MPL-2.0) is for code dependencies; a font file is data under licences code rules do not
cover (OFL-1.1 above all), so it needs an allowlist of its own.

## Decision Drivers

- The player gains no dependency and no network path: it reads font bytes from the document's assets alone (ADR-0148:
  measure only from asset bytes; the player never names a font host).
- Licences are checked, not remembered: a font that is not under an allowed licence cannot be bundled or offered.
- An offline file must render the same everywhere: the exact bytes that were measured are the bytes embedded.
- The studio works without a build step for fonts: a fresh clone has the bundled files and the catalog in the tree.
- Network-free tests: the Google route is mocked; nothing in `pnpm verify` reaches a font host.

## Considered Options

Bundled fonts:

1. **Depend on `@fontsource/*` at run time.** Maintained, hashed, per-weight files, but a production dependency for
   data, the code allowlist applies to the package (OFL-1.1 is not on it), and the player would resolve them by bare
   specifier.
2. **Vendor the files** once, with a manifest, from the `@fontsource` packages (OFL-1.1, per-family, woff2). The manifest
   records family, weight, style, file, SHA-256, SPDX licence and upstream version; a script re-vendors and verifies.
3. **Load from a CDN.** No: offline files and the player's no-network rule.

Catalog:

1. **Call the Google Fonts Developer API at run time** (an API key, a network call per open of the picker).
2. **A snapshot**: a JSON list generated by a maintainer script from the `google/fonts` repository's `METADATA.pb` files
   (family, category, weights, styles, subsets, licence directory), committed, with the repository commit recorded.

## Decision Outcome

- **Bundled fonts: option 2.** `packs/fonts-core` holds the files (`fonts/*.woff2`, Latin subset) and `fonts.json`.
  First set: **Inter** (sans), **Source Serif 4** (serif) and **JetBrains Mono** (mono), weights 400 and 700, with italics
  where the family has them, all **OFL-1.1**. `scripts/fonts/vendor.mjs` fetches the named `@fontsource` version from the
  npm registry, copies the files and writes the manifest and hashes; `--check` fails on a differing hash. The OFL text
  and each family's copyright line ship in the pack's `OFL.txt` and in the repository `NOTICE`.
- **A font-licence allowlist** beside the code one, in `thresholds.mjs` (`FONT_LICENSES.allow`: `OFL-1.1` and `Apache-2.0`, the content-asset
  licences of tech-stack.md §3 rule 1 for fonts; the Ubuntu Font Licence families of the Google Fonts repository are left out
  of the catalog rather than adding a licence the standard does not list). `check-licenses` reads every `fonts.json` and the
  catalog and fails a font whose `license` is not on it, a manifest entry without a hash or a licence, or a file whose
  hash differs. The code allowlist is unchanged.
- **The catalog: option 2.** `packs/fonts-core/catalog.json` lists the families under the allowlist only (name, category,
  weights, styles, subsets, licence, repository path) and the commit it was generated from;
  `scripts/fonts/build-catalog.mjs` regenerates it. It is loaded by the studio when the picker opens, never by the player,
  and never at build time.
- **Fetching a Google font is the studio's act**, through an injected `fetch` port so tests mock it. The studio asks the
  Google Fonts CSS API (v2) for the chosen family, weights and styles with a woff2-capable `User-Agent`, downloads the
  `fonts.gstatic.com` files it names, and stores **the exact bytes** as font assets of the document (content-hashed, with
  family, weight, style and the licence of the family). The CSS API answers with one file per unicode-range slice
  (`latin`, `latin-ext`, ...): the studio stores each slice it needs (`latin` by default, more when the user picks a
  subset) as an asset face with its `unicodeRange`, so a Google face is a set of slices, not one whole file. Each stored
  slice gets a metrics record from the same producer as an upload (below), so a Google font is measured on the metrics
  path, not by the canvas fallback. Nothing else in the editor or the player names `googleapis.com` or
  `gstatic.com`; a grep test over the player bundle enforces it.
- **Uploads** are WOFF2, TrueType (`0x00010000`, `true`) and OpenType-CFF (`OTTO`), recognised by their first bytes, not by
  extension or MIME type; a collection (`ttcf`), WOFF 1, a file over 5 MB or one whose tables do not parse is rejected
  with a diagnostic. The family, weight and style come from the `name` and `OS/2` tables. The **metrics producer** (a host tool of the editor,
  never the player; ADR-0148) writes the `FaceMetrics` record for every stored font file, uploaded or fetched. An uploaded font records the
  licence string the user gives (or `unknown`); it is the user's to hold, and it is never added to the catalog.
- **The registry** (`@fluxion/theme`, pure): `FontRegistry` maps a family to its source (`bundled`, `google`, `upload`) and
  faces (weight, style, file or asset id, licence). Loading (`FontFace`, invalidating the measurer cache when a face
  loads) lives in the render and editor layers, which own the DOM.
- **Attribution travels with the bytes.** Every font asset record carries the copyright line and the licence (SPDX id and
  the licence text or its URL); the bundled manifest and the catalog hold them. M10's embedding on save must write them
  with the embedded bytes (NFR-LIC-003: attribution is embedded in the files that use the font), so a saved document never
  redistributes a font without its notice; this is a hand-off to M10 row 13.
- **Deferred to M10.** Subsetting a font and embedding on save (FR-THM-008 "fetched and embedded on save"; the
  `.flux` and `.flux.html` writers) are the file format work of M10. In M9 a document keeps the files as stored (bundled and uploaded fonts whole, Google fonts as the slices fetched); the
  size cost is accepted until M10 subsets.

### Consequences

- Good: the player stays dependency-free and offline; a bundled font is a hashed, licensed file in the tree; the editor
  works without a font network.
- Good: the exact bytes fetched or uploaded are the bytes measured and embedded (no parity drift after M10).
- Neutral: a catalog snapshot ages; regenerating it is a maintainer step, and the studio's fetch fails soft (a diagnostic,
  the picker keeps the bundled and uploaded fonts) when Google changes a URL shape.
- Bad: vendored binaries enlarge the repository (a few hundred kB per family, woff2); the pack is separate so the player
  never loads it unless a document uses its fonts.
- Bad: unsubsetted assets make M9 documents with fonts large until M10.
- Neutral: a Google font's slices each have metrics; a character outside the fetched slices falls back to the family's
  next face as the browser does, and the metrics measurer's fallback covers it.

### Amendment (M9.16): uploads, and what a font asset carries

- **Reading a file** is `readFontFile` (`@fluxion/theme`, pure): the format from the first bytes, a collection, WOFF 1, a file over 5 MB and a file whose tables
  do not lie inside it refused with `FONT_FORMAT`, `FONT_TOO_LARGE` or `FONT_CORRUPT`. For TrueType and OpenType the family, weight and style come from
  `name` and `OS/2`. **A WOFF2 file keeps its tables as one Brotli stream, which a pure package without a dependency cannot open**: it is accepted by
  its signature and gives no names, and the family, weight and style come from the caller (the picker asks; the file name is the default).
- **A font asset** is an `asset` record (loose object, no schema change) with `mime` `font/woff2`, `font/ttf` or `font/otf` and a `font` field:
  `family`, `weight`, `style`, `source` (`upload` or `google`), `license`, `copyright` and `unicodeRange` when there are any, and **`metrics`**, the
  `FaceMetrics` of ADR-0148 recorded for these bytes. Its bytes are the host's (the asset store), as for an image.
- **The metrics producer** is `recordFaceMetrics` (`@fluxion/render`, DOM): the recording of `scripts/fonts/record-metrics.mjs` run in the page that will
  draw the text (the face loaded under a name of its own, measured in the DOM at 1000 px, removed again). The script and the producer are two copies of one
  algorithm; a browser test pins that the producer's numbers for the Roboto fixture equal the committed ones. `addFont` (`@fluxion/editor`) is the host
  tool: read, record, load the face, register its metrics, `asset.create` (one undo step). The player never records.
