# ADR-0036 — CLI contract v1: the operation layer, the full command set, exit-code meaning, the optional Chromium peer

## Context and Problem Statement

ADR-0147 gave the CLI its shape at M4 (two commands, `node:util.parseArgs`, exit codes 0/1/2/3, one `--json` reply per command validated by a Zod schema). M14 grows it to the command set of FR-CLI-002 (`compile`, `decompile`, `validate`, `lint`, `layout`, `render`, `catalog`, `migrate`, `convert`, `patch`) and makes it the operation layer the MCP server (M15) wraps one to one. 06-ai-authoring.md §9 sketched a `CliResult<T> { ok, command, version, diagnostics, data?, ms }` envelope before ADR-0147 existed. This ADR says which of the two stands, where the operations live, what each exit code means for the new commands, and how `render --png` depends on a browser without making the CLI heavy.

## Decision Drivers

- `--json` is a contract (AGENTS.md rule 6): the shipped reply of ADR-0147 must not change under the agents already reading it; additions must be additive.
- An agent branches on the exit code and the `ok` flag, never on text; a warning must not look like a failure.
- The MCP tools (M15) must return exactly what the CLI returns, from the same code, not by spawning the CLI.
- The CLI installs with no browser; raster output is opt-in (FR-AI-006).
- Output must be deterministic: no clock values or machine paths in a reply that a snapshot compares.

## Considered Options

1. **Replace the reply with the sketch of 06 §9.** One more field set (`version`, `ms`), but a breaking change for ADR-0147 readers and a nondeterministic `ms` in every snapshot.
2. **Keep ADR-0147's reply and extend it additively (chosen).** `apiVersion`, `command`, `ok`, `exitCode`, `result` or `errors`; one added optional field.
3. **A CLI framework with its own result conventions.** Rejected in ADR-0147 and unchanged.

## Decision Outcome

Option 2.

**The envelope is ADR-0147's.** `{ apiVersion: 1, command, ok, exitCode, result }` on success and `{ apiVersion: 1, command, ok: false, exitCode, errors[] }` on failure. One addition, additive (contracts.md: a new optional field is minor): a successful reply may carry `diagnostics: Diagnostic[]` for warnings and infos (exit code 0), so a lint run with warnings or a compile with notes is `ok: true` and still says what it found. There is no `ms` or `version` field: timing is nondeterministic and the version is `fluxion --version`. 06 §9 is updated to match.

**The operation layer.** `@fluxion/cli/ops` is a subpath export of the same package. Each operation is a plain function `(input, ports) => Promise<OpResult<T>>` where `OpResult<T>` is a new type of the CLI package, `{ ok: true; value: T; diagnostics: Diagnostic[] } | { ok: false; diagnostics: Diagnostic[] }` (ADR-0144's `Result` has one error and no success-side warnings, so it cannot carry them; an operation that wraps a core `Result` maps its error to a diagnostic), takes its file bytes as arguments (no `node:fs`), and returns the value that becomes the reply's `result`. A command is thin: parse arguments, read files through the host port (`host.ts`), call the operation, write any output file through the host, map the `OpResult` to an `Outcome`. The MCP tools call the operations directly with the same input and output Zod schemas (M15), so a tool's output equals the CLI's `--json` `result`.

**Commands and results.** Every command has a Zod reply schema in `output.ts` and a generated snapshot `packages/cli/schemas/<command>.output.json`; the aggregate `specs/schema/cli-result.json` is the union of them, generated by the same script (M14.14) and checked for drift. A command that writes a file returns the path it wrote as given (never an absolute resolved path). Commands that read stdin or write stdout use `-`.

**Exit codes.** 0 ok (warnings and infos allowed). 1 the input is wrong: validation or lint errors, `lint --min-score` below the minimum, a patch rejected whole (`FLX_PATCH_*`), a file that fails to parse, a file that cannot be read or written (`FLX_CLI_IO`, ADR-0147). 2 usage: an unknown command or option, a missing argument, a conflicting option, an unsupported format, an absent optional peer (below). The absent peer widens FR-CLI-005's "usage" on purpose: the command line is fine but cannot be run as asked; a client tells it from a malformed command line by the code `FLX_CLI_PEER_MISSING`, not by the exit code. 3 internal: an exception, with the stack on stderr only. A command never exits 0 after writing a partial output; outputs are written to a temporary name and renamed.

**Render and the optional browser.** `render --format html` needs nothing. `render --format png` (and later `svg` through the browser, `pdf`) loads Playwright with a dynamic `import('playwright')`; `playwright` is an optional peer dependency (`peerDependenciesMeta`), never a dependency, so installing the CLI downloads no browser. When it is absent, or Chromium is not installed, the reply is exit 2 with `FLX_CLI_PEER_MISSING` and a hint naming the install command; it never exits 1 (the input is fine) or 3 (nothing crashed). Rendering is per screen and optionally per step (`--screen`, `--step`), one file per screen named `<out>/<screen-id>[-<step>].png`.

**Diagnostics.** `FLX_CLI_USAGE`, `FLX_CLI_IO` and `FLX_CLI_INTERNAL` exist (ADR-0147). New codes are registered in `@fluxion/schema` and listed in `docs/reference/diagnostics.md` like all others: `FLX_CLI_PEER_MISSING`, `FLX_CLI_FORMAT_UNSUPPORTED` and `FLX_LINT_SCORE_BELOW_MIN`. The linter's own rules are `FLX_LINT_*` (M14.12).

### Consequences

- Good: agents already reading ADR-0147 replies keep working; new commands add result shapes only.
- Good: the CLI and the MCP server cannot drift, because they run the same operations over the same schemas.
- Good: a CLI install is small and offline; raster output costs a deliberate `npm i playwright`.
- Bad: warnings live in a second field on success, so a client must read `diagnostics` as well as `errors`.
- Bad: the dynamic import of an optional peer is invisible to bundlers and knip; the import is isolated in one module with an allow-list entry.
- Bad: outputs written through a temporary name need a rename port in the host (small, tested).

### Confirmation

M14.14 (the ops layer, the envelope with `diagnostics`, the exit-code matrix `exit-codes.test.ts`, `cli-result.json` drift), M14.15 and M14.16 (every command has a passing `fluxion <command> --json` test), M14.17 (`render --png` writes one PNG per screen; an absent peer is exit 2 `FLX_CLI_PEER_MISSING`).
