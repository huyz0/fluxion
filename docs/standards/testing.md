# Testing

> Read when: writing or changing a test, adding a fixture or golden file, touching a threshold
> or baseline, a test is flaky, or deciding which tier an acceptance criterion belongs to.
> Family: Quality · Related: [sdd.md](sdd.md), [ci-cd.md](ci-cd.md), [performance.md](performance.md)

Tests are the only thing that turns an agent's claim into evidence. The rules below keep them
fast, deterministic, traceable to requirements, and impossible to quietly weaken.

## 1. Tiers

| Tier | Tool | Runs in | May touch | Must not touch |
|---|---|---|---|---|
| **T0** pure unit | Vitest, `environment: node` | quick, pre-commit | pure packages, fakes for ports (`Clock`, `Random`, `TextMeasurer`, `FileSystem`) | DOM, real timers, network, `node:fs` (use in-memory FS port) |
| **T1** component | Vitest browser mode (Playwright provider, Chromium) / Storybook interaction (`play`) | pre-commit (changed), CI (all) | real DOM, one component or view subtree, fake stores | network, the full app shell, real `Date.now` |
| **T2** E2E | Playwright (chromium, firefox, webkit) | CI, milestone gates | built `apps/studio`, `.flux.html` via `file://`, local static server | external hosts (all blocked by `page.route`), real AI providers |
| **T3** visual | Playwright `toHaveScreenshot` in pinned Docker image + normalized SVG goldens | CI, milestone gates | fixture decks, embedded fonts | anything non-deterministic (see §5) |
| **T4** perf | `vitest bench`, Playwright traces | nightly, milestone gates | benchmark fixtures | shared CI runners for pass/fail below ±15 % noise |
| **T5** AI eval | `pnpm eval` | recorded in CI, live nightly | eval set in `eval/cases/`, recorded responses in `eval/recordings/` | live providers in CI |

Default to the lowest tier that can express the criterion. Needing DOM or I/O to test layout,
routing, or undo means the code is in the wrong layer — fix the layering, not the test.

| # | Rule | Enforced by |
|---|---|---|
| 1 | Tests are co-located: `foo.ts` → `foo.test.ts` (T0), `Foo.browser.test.tsx` (T1). E2E lives in `e2e/`, eval in `eval/`. | `vitest.config.ts` project globs |
| 2 | T0 files import nothing from DOM packages and set no `environment` override. | `check-layering.mjs` |
| 3 | Watch the test fail before implementing (red → green → refactor). | no gate — judgement |
| 4 | Test observable behaviour via public entry points, not private helpers or call counts. | no gate — reviewer |

## 2. Naming and traceability

```ts
describe('orthogonal router', () => {
  it('FR-CON-004: orthogonal route avoids obstacles', () => { … });
  it('FR-CON-004: WHEN target moves THE SYSTEM SHALL reroute within 16 ms', () => { … });
});
```

| # | Rule | Enforced by |
|---|---|---|
| 5 | A test that proves a requirement starts its title with the ID (`FR-…`/`NFR-…`). Helper tests without an ID are fine. | `check-trace.mjs` |
| 6 | Every **M** requirement of every completed increment is referenced by ≥ 1 passing test. Milestone gates call `check-trace.mjs --milestone M<n>` for the milestone's Req IDs. | `check-trace.mjs` |
| 7 | An EARS acceptance criterion maps to at least one test whose title quotes its trigger. | no gate — reviewer |

## 3. Fixtures and golden files

| Kind | Location | Rule |
|---|---|---|
| Document fixtures | `fixtures/docs/<name>.flux.json` (shared), `__fixtures__/` (package-local) | Built with builders from `@fluxion/schema/testing`; never hand-copied JSON when a builder exists |
| Format fixtures | `packages/format/fixtures/v<schemaVersion>/` | One per released schema version, never edited after release ([contracts.md](contracts.md)) |
| SVG goldens | `__golden__/<name>.svg` next to the test | Normalized: attributes sorted, numbers rounded to 2 dp, generated IDs replaced by `id-1…n`, whitespace collapsed |
| Screenshots | `e2e/__screenshots__/<browser>/` | Produced only in the pinned image |
| Eval cases | `eval/cases/*.yaml` + `eval/recordings/` | Recordings refreshed only by the nightly job or a task with that stated purpose |

| # | Rule | Enforced by |
|---|---|---|
| 8 | Updating a golden or screenshot (`-u`) is a threshold change: commit carries `Threshold-change: <which behaviour changed>`. | `check-drift.mjs` |
| 9 | Golden updates never ride along with unrelated changes; the reviewer sees the golden diff. | no gate — reviewer |
| 10 | Fixtures are small (≤ 50 kB each) and generated by a script when larger. | `check-size.mjs` |

## 4. Property tests

Use fast-check (`@fast-check/vitest`) for invariants. Seed is fixed in CI (`FC_SEED` printed on
failure); default 200 runs in pre-commit, 10 000 nightly. A failure's shrunk counterexample becomes a named
example-based case next to the property, in the commit that fixes it; the pre-commit ladder keeps the
seed and counterexample lines in its FAIL detail, so a local failure can be replayed with `FC_SEED`.

| Area | Required properties |
|---|---|
| geometry | transform ∘ inverse = identity (ε 1e-9); bbox contains all sampled outline points; intersection symmetric |
| layout | no overlap after overlap pass; deterministic for same input + seed; nodes inside container bounds |
| routing | orthogonal routes have only axis-aligned segments; routes never cross obstacle interiors |
| core / undo | any command sequence then full undo = initial document (NFR-REL-003); redo after undo = post state; every command emits record puts/deletes only (NFR-MNT-006) |
| format | `read(write(doc))` deep-equals `doc`; loader never throws on corrupted input (NFR-REL-002) |
| dsl | `compile(decompile(doc))` is equivalent to `doc` for the supported subset |

| # | Rule | Enforced by |
|---|---|---|
| 11 | A property failure is reproduced as a named example test before the fix. | no gate — reviewer |

## 5. Determinism

| # | Rule | Enforced by |
|---|---|---|
| 12 | **No sleeps.** No `setTimeout` waits, `page.waitForTimeout`, or polling loops. Use `vi.useFakeTimers()`, an injected `Clock`, `page.clock`, or web-first assertions. | Biome rule + `check-drift.mjs` grep |
| 13 | Randomness is seeded (`Random` port, fast-check seed); IDs come from a deterministic generator in tests. | pure-package lint bans `Math.random` |
| 14 | Visual tests: pinned Playwright image, viewport 1280×800, `deviceScaleFactor: 1`, locale `en-US`, timezone `UTC`, `reducedMotion: 'reduce'`, animations disabled, embedded fonts awaited via `document.fonts.ready`, `maxDiffPixelRatio ≤ 0.001`. | `playwright.config.ts` shared preset |
| 15 | Prefer structural SVG goldens over screenshots; use screenshots for what only pixels show (text rendering, filters, compositing). | no gate — judgement |
| 16 | Animation is tested by sampling `sample(model, t)` at fixed times, never by waiting in real time. | no gate — reviewer |

## 6. Floors

| Scope | Lines | Branches | Mutation (nightly, tzap: ADR-0146) |
|---|---|---|---|
| schema, geometry, core, layout, routing, anim | ≥ 90 % | ≥ 85 % | ≥ 70 % (core, schema, layout, routing) |
| format, dsl, theme | ≥ 90 % | ≥ 85 % | — |
| render, player | ≥ 80 % | ≥ 75 % | — |
| editor | ≥ 70 % + E2E flows | ≥ 65 % | — |

| # | Rule | Enforced by |
|---|---|---|
| 17 | Floors live in `scripts/gates/thresholds.mjs` and `.harness/baselines/mutation.json` and only move up. | `check-drift.mjs` |
| 18 | Coverage is a floor, not a goal: a test that executes code without asserting on its result is a defect. Surviving mutants in touched files are reviewed. | nightly `pnpm mutate --check`, reviewer (`pnpm mutate --package <dir> --from <base>`) |

## 7. E2E conventions

- **Page objects** in `e2e/pages/` (`EditorPage`, `PlayerPage`, `InspectorPanel`). Specs call
  intent-level methods (`editor.addShape('rect', {x: 100, y: 100})`), never raw selectors.
- Locators: `getByRole` / `getByLabel` first, `data-testid` second, CSS never.
- Each spec is independent: fresh context, fixture document loaded via `EditorPage.open(fixture)`.
- Network: `page.route('**/*', …)` blocks everything but the local server by default.
- One user journey per spec file; file name `<area>.<journey>.spec.ts`
  (`connectors.reroute-on-move.spec.ts`).
- Every spec runs axe on its final state unless tagged `@no-a11y` with a reason.

## 8. Flakes and deletion

| # | Rule | Enforced by |
|---|---|---|
| 19 | **Zero-flake policy.** A test that fails then passes on retry is a flake. Within 24 h it is quarantined (`test.fixme` / `it.skip` with `// QUARANTINE M<n>.<k>`) **and** a backlog row is added to fix it. | `flake-report.mjs`, `check-drift.mjs` (quarantine needs a live row) |
| 20 | Quarantined tests count against the milestone gate; a milestone cannot complete with open quarantines it introduced. | `m<n>-complete.mjs` |
| 21 | **Never delete or weaken a test to make a change pass.** Loosened assertions, widened tolerances, and added `skip` count as weakening. Genuine removal needs `Removes-test: <reason>`. | `check-tests-kept.mjs`, reviewer |
| 22 | Never claim a test passed without running it; paste the command and its summary line as evidence. | no gate — judgement |
